How to kill the process on a port on a Mac

This stops the server that is listening on port 3000, and nothing else.

kill $(lsof -t -iTCP:3000 -sTCP:LISTEN)

lsof -t prints only the PID, and kill asks that process to quit. Use your own port in place of 3000.

Why not lsof -t -i :3000

You will see this version in many answers. Without -sTCP:LISTEN it also matches every program that is connected to the port, such as a browser tab. Running kill on that list can close your browser along with the server.

If it does not quit

Wait a few seconds first, because some servers close connections before they exit. Then check:

lsof -nP -iTCP:3000 -sTCP:LISTEN

If it is still there, force it with kill -9 and the PID. This gives the program no chance to clean up, so use it last.

If it keeps coming back

  • A watcher such as nodemon or a process manager restarts it. Stop the watcher too.
  • The server has workers, like uvicorn or gunicorn. Stopping one process can leave a worker holding the port. Stop the parent and its children.
  • It is a Docker container. Use docker stop with the container name. Killing the process that holds the port does not stop the container.

Check before you kill

It is easy to stop the wrong thing, especially a database that other servers are using. Look at the process first with ps -p PID -o command=. See how to find what is using a port.

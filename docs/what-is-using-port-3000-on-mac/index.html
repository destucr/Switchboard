What is using port 3000 on a Mac?

Run this in Terminal. It prints the process that is listening on port 3000, or nothing if the port is free.

lsof -nP -iTCP:3000 -sTCP:LISTEN

The line it prints has the program name, its PID (the number you need to stop it) and the user. -nP skips name lookups so it answers fast. -sTCP:LISTEN keeps only the server itself, not your browser or anything else connected to it.

Find which project it belongs to

A PID alone does not tell you which of your projects started it. Ask for its folder and its full command:

lsof -a -p 12345 -d cwd
ps -p 12345 -o command=

Replace 12345 with the PID. The first line shows the folder it runs from, and the second shows the command, for example node ./node_modules/.bin/next dev.

If nothing shows up

  • The port is free. Whatever failed to start may be using a different port.
  • The process belongs to another user. Try the same command with sudo.
  • It runs in Docker. Check docker ps and look at the Ports column.

Port 5000 or 7000 on a Mac

On recent versions of macOS, ports 5000 and 7000 are often taken by AirPlay Receiver, which shows up as ControlCenter. If a Flask or similar app cannot use 5000, turn off AirPlay Receiver in System Settings, under General, then AirDrop & Handoff. Or run your app on another port.

What to do next

If it is something you forgot about, stop it. If you need both running, start yours on another port. If your app crashed with an error, see how to fix EADDRINUSE.

Or do it in Switchboard

Open Switchboard from the menu bar and type 3000 in the filter box. It shows whether the port is free and, if not, which server holds it, which project it belongs to and how long it has been running. No PID hunting.

Switchboard is a free, open source menu bar app for Mac. Install it with brew install --cask destucr/tap/switchboard.

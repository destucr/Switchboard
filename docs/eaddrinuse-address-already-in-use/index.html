Fix “EADDRINUSE: address already in use” on a Mac

It means another process is already listening on the port your server asked for. Only one program can use a port at a time.

You may see it as Error: listen EADDRINUSE: address already in use :::3000 in Node, OSError: [Errno 48] Address already in use in Python, or bind: address already in use in Go. They are the same problem.

1. Stop what is using it

Often it is your own server from a terminal you closed, or a second copy that started by accident. Find it and stop it:

lsof -nP -iTCP:3000 -sTCP:LISTEN
kill PID

More detail in how to find what is using a port and how to kill it safely.

2. Use another port

If the other process should keep running, start yours somewhere else:

PORT=3001 npm start
vite --port 3001
next dev -p 3001
flask run --port 5001
rails server -p 3001
python3 manage.py runserver 8001
php artisan serve --port=8001

3. Look for the cause

  • Ports 5000 and 7000: on recent macOS, AirPlay Receiver uses them. Turn it off in System Settings, under General, then AirDrop & Handoff.
  • A leftover process: a crash or a closed terminal can leave a server running with nobody watching it.
  • Docker: a container may publish the same port. Check docker ps.
  • Reload tools: a watcher can start a new copy before the old one has quit.

Or do it in Switchboard

If you start a stopped server whose port is taken, Switchboard says who is using it and offers the next free port. For a running server, double click its port number to move it to another port, and press Undo if you change your mind.

Switchboard is a free, open source menu bar app for Mac. Install it with brew install --cask destucr/tap/switchboard.
